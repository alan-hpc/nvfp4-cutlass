BF16 → Two-NVFP4 Dual-A Grouped-MoE GEMM

真实 MoE 推理中进入 expert GEMM 的激活是 BF16。本算法把 BF16 激活在 GEMM mainloop 内在线分解为 两遍 NVFP4(MSD:高位 + 残差),对 NVFP4 权重做两次 block-scaled MMA 累加到同一累加器, 从而让 BF16×NVFP4 的 mixed-input GEMM 跑在 FP4 tensor core 上。本文同时覆盖无 global workspace 的 fused 路径，以及 transform 只做一次、跨 N tile 复用 A0/A1 的 hybrid 路径。

真实 NVFP4 配置 · static per-tensor 与 dynamic K/16 是两层尺度

NVIDIA 的 NVFP4 数值模型不是只有一个 E4M3 scale，而是 FP32 per-tensor global scale × E4M3 per-block scale × E2M1 data：

x̂b,i = qb,i · Sb · G，  G = Aglobal / (448·6)，  Sb = QE4M3((ab/6)/G)

其中 A_global 是 FP32 per-tensor amax（可以由校准得到后静态保存）， a_b=max|x_b| 仍是运行时每 16 元素的 block amax。ModelOpt 的基础 nvfp4.yaml 明确配置 block_sizes[-1]=16, type=dynamic, scale_bits=e4m3； 所以“per-tensor 是静态的”不等于可以删掉 K/16 reduction。

本模型配置恰好可折叠：NVIDIA 的 expert input-scale1 recipe 把 activation constant_amax 固定为 2688 = 448×6，故 G_A=1。 当前 fused kernel 已按这个特例实现：不加载、不乘 activation global scale，直接计算 S_A=Q_E4M3(a_b/6)。权重的静态 G_W 则保留到 epilogue，每 expert 只读一次并乘最终 accumulator。

Algorithm 1 · BF16 block → 两遍 NVFP4(MSD 分解,per 16-element block)

Algorithm 1Dual-NVFP4 Decomposition of one BF16 block
Require: x ∈ BF1616  （激活的一个 K/16 块）
Ensure: (q0, s0), (q1, s1)，其中 q0,q1 ∈ FP4-E2M116，s0,s1 ∈ E4M3
1:M ← maxi |xi| ▷ block 的 ∞-范数
2:s0 ← rndE4M3( M / 6 ) ▷ 第一遍块尺度；6 = E2M1 有限最大值
3:q0i ← rndE2M1( xi / s0 ) ▷ 高位遍(most-significant)
4:ri ← xi − decE2M1(q0i) · s0 ▷ 残差
5:s1 ← s0 / 8 ( = s0 · 2−3, derived) ▷ 可选 residual_amax: s1 ← rndE4M3(maxi|ri| / 6)
6:q1i ← rndE2M1( ri / s1 ) ▷ 残差遍(residual)
7:return (q0, s0), (q1, s1)
重构：  x̂i = decE2M1(q0i)·s0  +  decE2M1(q1i)·s1
第 5 步的 /8(derived_div8)因子来自 E2M1 非均匀格点的残差界：E2M1 顶端间隔 2.0， 最坏残差 ‖r‖∞ ≤ s0，故 s1 = s0/8 让 r/s1 落在约 [−8,8]（少量 clip 到 ±6）。 论文原始的 β=α/16 是为均匀 E1M2 格点调的，直接搬到 E2M1 会过量 clip；residual_amax 精度最好但多一次 reduction。 零块（M=0）把尺度钳到最小正 E4M3（2−9）；derived_div8 先把 s0 钳到 8·2−9，保证 s1=s0/8 不会下溢为 0，因此 q0=q1=0 且不会产生 inf/NaN。

Require: Abf16[M,K]，(Wfp4, SW, GW)[E]，m_indptr[E+1]，tile (TM,TN,TK)
Ensure: C[M,N]（BF16），C = A · Wᵀ 的两遍 NVFP4 近似
1:for expert e in 0..E−1:
2: for 每个输出 tile (m_tile ⊂ [offe,offe+1), n_tile):
3: Acc ← 0 ▷ TMEM 累加器
4: for k_tile in 0..K/TK−1:
5: load Abf16[m_tile, k_tile] ▷ TMA，BF16，2 byte/elem，无 A-scale
6: load Wfp4[n_tile,k_tile], SW[n_tile,k_tile] ▷ 每逻辑 K tile 只 load 一次
7: // producer：在 mainloop 内对每个 K/16 块跑 Algorithm 1
8: (A0,SA0),(A1,SA1) ← decompose(A_tile) ▷ producer-local，不落 global
9: // 两遍 block-scaled MMA，共用同一个 W / S_W 片段

等价数学：  C = A0 Wᵀ + A1 Wᵀ，   A0 = dec(q0)·s0，  A1 = dec(q1)·s1，  W = dec(Wfp4)·SW·GW

统一流水 · Algorithm 1 ⊕ Algorithm 2 融合为一条 B300 warp-specialized pipeline

把两个算法合成一条流水：Algorithm 1(BF16→2×NVFP4 分解)不是独立 kernel，而是 producer 阶段逐 K/16 块跑的 transform；Algorithm 2 是承载它的融合 GEMM mainloop。当前 B300(SM103)实现使用 10 warps / 320 threads：warps 0–3 与 6–9 在 mainloop 中共同做 transform，warp 4 发 MMA， warp 5 发 TMA；排空 mainloop 后 warps 0–3 再做 epilogue。一个 transform stage 必须把 A0/A1/SFA0/SFA1 全部写完才 commit，所以实际稳态重叠是 transform(k+1) ↔ 两遍 MMA(k)，不是同一 stage 内 A1 transform ↔ A0 MMA。

性能分析 · 非 MMA 操作能被隐藏吗

真实实现的结论：TMA 与 stage k+1 的 transform 能和 warp 4 消费 stage k 重叠；S2T 是 warp 4 自身的串行子阶段； epilogue 在最后一个 K stage 之后才由 warps 0–3 执行，同一 CTA 内不能被 mainloop 隐藏。 IKET 显示 warp 4 的 mainloop 时间中有 69.7%在等待 transformed-A stage，说明新增的 transform(BF16→2×NVFP4)位于关键路径。

1. 一个物理线程究竟处理哪些 A

# warps 0–3 → chunk_group 0; warps 6–9 → chunk_group 1 transform_chunk_group = warp_idx // 6 transform_tidx = tidx - transform_chunk_group * 192 transform_chunk_begin = transform_chunk_group * transform_chunks_per_thread half_k_groups = tile_k // 8 # H = 16 row_groups = 128 // half_k_groups # 8 K_start = (transform_tidx % H) * 8 row = row_groups * chunk + transform_tidx // H
线程坐标
H=TK/8=16
kstart(t)=8·(t mod H)
m(t,c)=8c+⌊t/H⌋
工作量
8 chunks/thread × 8 BF16/chunk = 64 BF16/thread/K-tile
256 transform threads × 64 = 128×128 个 A 元素

一个 thread 只持有一个 K/16 block 的一半：lane t 处理 k=16g…16g+7，相邻的 t⊕1 处理 k=16g+8…16g+15。所以一个 lane-pair 每个 chunk 合作完成一个 16 元素 block， 每个 pair 在一个 K-tile 内完成 8 个 block。

2. 默认 derived_div8 热循环

x = tArA_load[(None, chunk)].load().to(Float32) # 8× BF16 → FP32 half_amax = abs(x).reduce(MAX, Float32(0.0), 0) amax = fmax(half_amax, shuffle_sync_bfly(half_amax, 1)) s0 = E4M3(fmax(amax * (1.0 / 6.0), 8 * 2**-9)) s0f = s0.to(Float32) inv_s0 = rcp_approx(s0f) x_scaled = x * inv_s0 q0v = x_scaled.to(E2M1) # hardware FP4 cvt s1 = E4M3(s0f * 0.125) q1v = ((x_scaled - q0v.to(Float32)) * 8.0).to(E2M1) autovec_copy(q0v, A0_smem) autovec_copy(q1v, A1_smem) SFA0[row, k16] = s0 SFA1[row, k16] = s1

令一个真实 K/16 block 为 xb=(xb,0,…,xb,15)， Q4 表示饱和就近舍入到 E2M1， Qs 表示舍入到 E4M3。与源码逐项一致的公式是：

ab = max0≤i<16|xb,i|，  s0,b = Qs(max(ab/6, 2−6))
ρb = rcp_approx(float(s0,b))，  ũb,i = float(xb,i)·ρb，  q0,b,i = Q4(ũb,i)
s1,b = Qs(float(s0,b)·2−3)，  q1,b,i = Q4((ũb,i−float(q0,b,i))·23)
x̂b,i = float(q0,b,i)·float(s0,b) + float(q1,b,i)·float(s1,b)
精确性边界：代码并没有做精确的 x/s0，而是 x·rcp_approx(s0)；s1 也会再次经过 E4M3 rounding。 因此文档里的简写 q0=Q4(x/s0) 与 s1=s0/8 是算法语义，上面的 ρ、ũ 和 Qs 才是当前 GPU 实现的逐操作公式。

3. 源码级成本：冗余在哪里

每 lane、每 8 元素 chunk源码级工作是否与 lane⊕1 重复
取块尺度8×abs + local max reduction；1×shuffle；1×fmax；乘 1/6、floor、E4M3 castlocal max 不同；shuffle 后的 amax、s0 完全相同
第一遍1×scalar approximate reciprocal；8×scale；8×E2M1 conversionreciprocal 相同；8 个 q0 各自不同
第二遍s1=s0/8 + E4M3 cast；8×FP4→FP32；8×sub；8×mul；8×E2M1 conversions1 相同；8 个 q1 各自不同
输出16 个 FP4 元素 + SFA0/SFA1 各一次FP4 不同；两条 lane 的 两个 scale store 都是同地址、同数值

以上工作每个物理线程重复 8 次。当前 lane-pair 必须各自量化 8 个不同元素；两条 lane 虽然得到相同的 s0 / rcp(s0) / s1，但在 SIMT 上一条标量源码操作本来就是整个 warp 发射一条指令。把它 predicate 成只有偶数 lane 执行不会把“一条 warp 指令”变成半条，反而还要增加 predicate 和 broadcast。因此这里是数据结果重复，不等于 issued instruction 可减半。stage 尾部还有一次 256-thread named barrier、SMEM proxy fence 和 pipeline commit；它们是每个 K-tile 一次，不是每个 block 一次。

Transform 的 break-even

两者在不同硬件单元并行,藏得住 ⟺ transform 的 CUDA-core cycles ≤ 两遍 MMA 的 tensor-core cycles。 关键:transform 只随 TM·TK,与 TN 无关;MMA 随 TM·TN·TK。TM、TK 消掉后只剩 TN:

w·TM·TK / Pcuda ≤ 2·TM·TN·TK / Ptc   ⟹   TN ≥ w · Ptc / (2·Pcuda) ≈ 65 · w   （w = 每个 A 元素的 transform 指令数）

单 SM 估值:Ptc ≈ 1.6–1.7×10⁴ FP4-MAC/cycle（B200 9 PFLOPS / 148 SM / 1.8 GHz）,Pcuda = 128 FP32-FMA/cycle。 B300 的 FP4 tensor 更快 → Ptc↑ → break-even TN 更高 → transform 更难藏。

transform 实现w（FMA-eq/元素）需要的 TN判定
硬件 e2m1 cvt + 乘倒数 + warp-reduce amax + s1=指数移位~4≥ ~260TN=256 勉强,TN≥512 舒服
朴素 FP32（div / round / dequant / sub / 再 quant）~10≥ ~650常规 tile 藏不住 → transform-bound
两个反直觉点: ① dual-A 的「两遍 MMA」反而帮忙——tensor core 忙了 2×,给 transform 的影子也长了 2×（公式里的因子 2）。 ② 硬件越强越难藏:B300 FP4 tensor 更快,break-even TN 被推高。
当前 profiler 直接证明 transform 在关键路径：关闭 MMA 的 transform-only 时间几乎等于完整 kernel，而只保留两遍 MMA 明显更短。

本轮负结果同样保留：把完整 register staging tensor 改成两个 8-BF16 rolling buffer 后， CuTe/ptxas 生成的整份 SASS SHA-256 逐字节相同，transform 区仍有 8×LDS.128、8×STL.128、0×LDL。这说明 8 个 STL.128 是后端对展开后 SSA 活跃区间的落栈选择，不是源码 tensor 容量直接造成；该改写没有真实收益，已从源码回退。static G_A=1 则本来就没有生成 load/multiply，所以也不存在可再删除的一条 runtime 指令。
为什么 FP16 没有更快：数值范围并不是问题——static A_global=2688 内的 BF16 activation 可以安全转为 FP16，归一化值也只有约 ±6。问题是当前 CuTe/ptxas 没把这段 8-element tensor 表达式收敛成更短的 packed-half 序列。 全 FP16 vector 版本的 F2F/F2FP 从 248 增到 320，并产生大量额外 HADD2/HMUL2/HFMA2；q1-only 版本也要先把 x_scaled 和 q0 从 FP32/FP4 转成 FP16，多出的 32 条 conversion 超过了 half arithmetic 节省。当前 FP32 向量一次转换后同时复用于 amax、q0 与 q1，机器码反而更短。
只靠 fused CTA 微调，1.1× 目标尚未达到。 PyTorch profiler 看到 FlashInfer MXFP4 的实际 cuDNN kernel 约 14.07 μs；其 API event 时间会在约 0.060–0.123 ms 间双峰，差值主要是 host dispatch gap， 不能拿较慢的 0.12 ms 峰值宣称 dual 已追平。当前 dual GPU kernel 约 0.115–0.120 ms， 仍约为 MXFP4 kernel 的 8×。因此实现了下面的 hybrid 路径，让同一份 A transform 跨所有 N tile 复用。

Hybrid：一次全局 transform + 两个 NVFP4 GEMM

结构性优化位于 dual_nvfp4_hybrid.py：Triton 一次生成全局 A0/A1/SFA0/SFA1，并直接写 FlashInfer/cuDNN 需要的 128×4 scale layout；随后两个 grouped NVFP4 GEMM 复用同一份权重，最后做一次 BF16 add。它用 global workspace 换掉 fused 方案中“每个 N tile 重算一次 transform”的放大项。benchmark 的 --cuda-graph 会捕获整条 steady-state 路径，排除四次 Python/API dispatch gap。

让它藏住的设计杠杆

  • 压低 w：硬件 FP4 转换、rcp_approx(s0)、归一化域 residual、amax shuffle；并用 distance=2 的 shared→register 软件预取减少地址与循环指令。
  • TN 受 TMEM 硬约束：TN=256 时 accumulator 256 列，SFA0/SFA1 各 8 列、SFB 16 列，共 288/512；TN=384 共 424/512。TN=512 的 accumulator 已占满 512 列，没有 scale 空间。
  • 跨 stage 双 buffer + 8 producer warps：MMA 消费完整 stage k 时，两个 transform group 生成完整 stage k+1；不能假设同一 stage 的 A0/A1 边产边吃。
  • N-reuse 调度：这是达到 1.1× 的结构性方向。实测 N=768 时 TN=384 从 0.1906 ms 降到 0.1365 ms；但 N=1024 的 768+256 双 launch（0.2119 ms）和 pad 到 1152（0.2673 ms）都回退，当前不能设为默认。
  • hybrid 已实现：一次写出全局 A0/A1/SFA0/SFA1，再调用两个优化 NVFP4 GEMM；它把 transform 从每个 N tile 一次降为整个 A 一次，并成为大 M 主形状的最快路径。

关键不变量

  • fused 路径无 global dual-A：A0 / A1 / SA0 / SA1 只存在于 producer stage，consume 完即释放。
  • hybrid 路径一次性 global dual-A：四个 workspace 只由 transform 写一次，并被两个 cuDNN GEMM 跨全部 N tile 复用；scale 直接按 128×4 物理布局写出，无额外 swizzle kernel。
  • W 复用：一个 W / SW tile 喂两遍 MMA（一个 tCrB 片段 feed 两条 bsmma），逻辑 B 流量保持单份。
  • 累加寄存器共享：A0×W 用 accumulate = (k_tile ≠ 0)、A1×W 恒 accumulate = true，两遍落进同一 TMEM 累加器。
  • 单次 epilogue：所有 K tile 的两遍都累加完才 commit 一次、单次 BF16 store，无 C0/C1 中间输出。

Ground truth（验证用，不在 kernel 内）

Cref = Abf16 · ( dec(Wfp4) · SW · GW )ᵀ   （FP32 累加）

误差评估对比三条：Cref（BF16 原值 × dequant 权重，FP32）↔ Algorithm 2 输出（两遍 NVFP4）。 ground truth 必须用 BF16 原值，不能引入任何 FP8 中间量化，否则会低估真实误差。
